# Raw materials, source facilities, and transport

The data layer is small and authoritative. `src/data/index.ts` exports these raw-related symbols (verified):

- `rawMaterialSources: Map<ItemId, RawSourceConfig>` — binds each raw to its in-game source facility + optional `ratePerMinute` override. Canonical "what items are raws" anchor.
- `rawAvailabilityByDomain: ReadonlyMap<DomainId, ReadonlySet<ItemId>>` — per-region raw availability. **Sole source of truth for "what counts as a raw in this plan"**: App.tsx threads `.get(currentDomain)` into the calc layer as the `rawMaterials` parameter. Subset-of-rawMaterialSources by invariant; tests enforce both soundness + completeness.
- `costlessRaws: ReadonlySet<ItemId>` — `items.filter(isLiquid) ∩ rawMaterialSources.keys()`. Currently `{item_liquid_water, item_liquid_acid}`. Auto-extends for liquids only. TYPE classification (region-independent); the LP zero-cost bias applies wherever the recipe runs. **Gas raws (1.4) are deliberately excluded**: gas vents are node-capped like ore spots (see `defaultRawCapsByDomain`), so gas consumption pays normal LP raw cost and respects the caps.
- `producibleRaws: ReadonlySet<ItemId>` — `rawMaterialSources.keys() ∖ costlessRaws` (opt-out; the costless liquids are excluded because producing an infinite/free raw never makes sense). A member with an ACTIVE producer (today: Xiragen via the transmuters) becomes a balance-constrained item fed by a capped vent/mine-supply LP variable ALONGSIDE its producer recipes — the LP mines the vent up to the node cap and crafts only the overflow (a per-unit craft surcharge keeps mining preferred). Producer-less members (ores) stay pure leaves. TYPE classification; `CalculateProductionPlanOptions.producibleRaws` overrides it (tests pass `new Set()`). Full mechanism in `.claude/rules/solver.md` (§Producible raws).
- `forcedDisposalItems: Set<ItemId>` — items that must net to zero (`{item_liquid_sewage, item_liquid_xiranite_lowpoly, item_liquid_xiranite_poly}`). Items in this set with a consumer in the graph get strict-equality LP semantics (`prod - cons = targetRate` with two-sided slack); items with no consumer fall back to `min: 0`. See `.claude/rules/solver.md` for the constraint emission.
- `bootstrapFacilities: ReadonlySet<FacilityId>` — facilities whose recipes bypass the chain-reachability check (currently `{seedcollector_1}`). See `.claude/rules/solver.md` for semantics.
- `facilityRecipeVariants: ReadonlyMap<FacilityId, { default; toggled }>` — per-facility recipe-variant pairs gated by a structure toggle. Today: `LIQUID_CLEAN_GATE_1` → `{ default: LIQUID_CLEAN_GATE_1_DISPOSAL, toggled: LIQUID_CLEAN_GATE_1_BYPRODUCT }`. Drives the App-side variant filter + the calculator-side defensive filter; see `.claude/rules/domain-settings.md` for the bridge and `.claude/rules/solver.md` for how the LP picks the active variant.
- `mapPlacedFacilities: ReadonlySet<FacilityId>` — facilities that are fixed map structures, excluded from `aggregateBinTotals.totalTiles`. Aliased to ALL region-subsystem facility ids **by construction of the extractor** (every `regionFacilities` entry comes from a map structure in the game data); split into an explicit subset if a build-grid region facility ever appears.
- `defaultRawCapsByDomain` (re-exported from `src/data/raw-caps.ts`, AUTO-GENERATED by `extract:raw-caps`) — per-region max mining output per raw, in items/min.

**Removed**: `forcedRawMaterials` (the global "all raws" Set) was dropped in the per-region refactor. Tests use `new Set(rawMaterialSources.keys())` as the convenience equivalent (extracted to `src/tests/lib/utils.ts` as `ALL_RAWS`); production code receives `rawMaterials` as an explicit parameter at every calc-layer call site.

## Source-facility assignment rules (verified)

- Solid ore/sand → `unloader_1` (Depot Unloader, 0 W, 30/min belt capacity)
- Most liquids → `pump_1` (Fluid Pump, 10 W, 60/min)
- Acid → `pump_2` (Acid Resistant Pump Mk II, 20 W, 60/min)
- Gases (1.4) → `gas_pump_1` (Gas Extractor, 0 W, 20/min — one unit per 3 s). Only Inergen (`item_gas_inert`) + Xiragen (`item_gas_xiranite`): the 3 Acridgen vents have no supporting extractor, so Acridgen is craft-only (Transmuting Unit from Liquid Acid). Wuling-only (`gas_pump_1.domains`); node-capped at max dev: **Inergen 460/min (23 vents), Xiragen 100/min (5 vents)** — these are panel-verified **manual overrides** (`MANUAL_CAP_OVERRIDES` in `scripts/extract-raw-caps.ts`, surfaced inline in `raw-caps.ts`), NOT scene-counted: the 1.4 "Homecoming" Wuling gas vents + new-region nodes aren't in the extractable data (its lone gas scene `map02_lv008` is a gas-environment cluster, not the mineable vents; no table stores regional caps). Wuling Cuprium (420/min) is overridden the same way (18 base + new-region copper). The overrides self-retire — the extractor warns to delete them once refreshed data reproduces the value.

Per-facility throughput defaults to transport capacity (30/min belt, 120/min pipe). Liquid pumps cap at 60/min — half the pipe capacity — so they REQUIRE `ratePerMinute: 60` in `rawMaterialSources` (lines 102-103). The pump's one-cycle-per-second rate in the game data is the source of truth for the 60/min rate.

## Per-region mining caps (raw limits)

- **Defaults**: `defaultRawCapsByDomain` (`src/data/raw-caps.ts`) carries each region's max mining output per raw. **User overrides**: `useDomainSettings().rawLimits.overrides` (per item+region; see `.claude/rules/domain-settings.md`).
- **Merge**: `buildRawMaterialCaps` (`src/lib/raw-limits-helpers.ts`) resolves override-wins-over-default for the current domain, filtering invalid values and other-region/malformed keys. The result threads App.tsx → `useProductionPlan` → `calculateProductionPlan` as `options.rawCaps`.
- **LP side**: raw caps are SOFT constraints (`SLACK_PENALTY`) — over-demand plans stay solvable and diagnosable. The calculator emits the user-facing `raw-over-cap` warning into `plan.warnings` at plan assembly (`computeLimitViolations`, plan-helpers.ts); the target optimizer's feasibility check treats any raw-over-cap as infeasible (it scans the same warnings — see `.claude/rules/optimizer.md`).
- Units are items/min everywhere (defaults, overrides, LP, warnings). Blank override = use default; raws without a default are unlimited.

## Transport capacities (`src/lib/utils.ts:19-31`)

- `TRANSPORT_BELT_CAPACITY = 30` items/min
- `TRANSPORT_PIPE_CAPACITY = 120` items/min
- `getTransportCapacity(item)` — branches on `item?.isLiquid || item?.isGas` (1.4: gases share the pipe network at 120/min).

Pump throughput (60/min) and pipe capacity (120/min) are **distinct concepts**:
- `getRawSourceRate(itemId, item)` (`src/lib/utils.ts:65`) — per-facility rate. Reads `rawMaterialSources.get(itemId)?.ratePerMinute`, falls back to `getTransportCapacity(item)`.
- `getTransportCapacity(item)` — per-belt/per-pipe rate.

One pipe carries two pumps' worth of flow (120 vs 60). Pickup count uses `getRawSourceRate`; edge labels use `getTransportCapacity`.

## Source-facility power folding

`aggregateBinTotals` (`plan-helpers.ts:164`) folds pickup-point pumps (`pump_1`, `pump_2`, `gas_pump_1`) and depot unloaders (`unloader_1`) into `perFacility` and `totalPower`. Pickup counts respect `ceilMode`: ceiled physical pickups when `ceilMode=true`, fractional theoretical when `ceilMode=false`. **Do NOT re-sum pickup power at the caller.** `PUMP_CATEGORIES` (`plan-helpers.ts`) is `{25, 26, 41}` — fluid pumps + the 1.4 Gas Extractor — all deployed on resource spots: zero grid tiles, counted as pump pickups (not depot ports).

## ID naming conventions

- Item IDs: `item_<category>_<subcategory>_<modifier>` (e.g. `item_copper_enr_powder`).
- Recipe IDs: `<facility_type>_<output>_<tier>` (e.g. `pool_xiranite_poly_1`).
- Facility IDs: `<type>_<tier>` (e.g. `pump_1`, `unloader_1`, `crucible_2`).
- Keep enums in `src/types/constants.ts` alphabetised.

## Generated vs region facilities

`src/data/facilities.ts` is fully auto-generated (`pnpm run extract:facilities`) from the game data. **Hand edits will be clobbered the next time the facility-extraction script is run.** Region-subsystem facilities not in the roster (today: `LIQUID_CLEAN_GATE_1`, modeling the three Wuling sewage inlet gates as one capped facility) live in `src/data/region-subsystems.ts` (`regionFacilities`, itself auto-generated by `pnpm run extract:structures`), alongside their recipe variants (`regionRecipes`).

The `@/data` barrel concatenates them with a region-wins dedup filter (`facilities = [...generated.filter(f => !regionFacilityIds.has(f.id)), ...regionFacilities]`; same pattern for recipes). Consumers MUST import `facilities` / `recipes` from `@/data`, not from `@/data/facilities` / `@/data/recipes`, or they'll miss the region entries.

**Naming convention for region entries**: use the canonical upstream game building ID verbatim. When a single LP-side facility collapses multiple in-game buildings (because they're functionally identical for solver purposes), name it after the tier-1 / first variant — mirrors how `liquid_cleaner_1` represents the Water Treatment Unit when game tiers 2/3 exist. The dedup filter is the structural backstop in case a future maintainer adds the canonical id to the facility-extraction allowlist (deliberately discouraged).

## DO NOT

- DO NOT add to `rawMaterialSources` without confirming the item has no in-game production recipe AND picking a real source facility. Wrong additions silently break upstream chains. Solids → `unloader_1`; liquids → `pump_1` (most) or `pump_2` (acid). Adding to `rawMaterialSources` also requires adding to at least one region in `rawAvailabilityByDomain` (the completeness test fails loudly otherwise).
- DO NOT reach for a global "all raws" Set — there isn't one anymore. The per-region `rawAvailabilityByDomain.get(currentDomain)` is threaded explicitly through the calc layer; consumers receive it as a parameter.
- DO NOT pass `item` to `getPickupPointCount`. Signature is `(demandRate, perFacilityRate)` — get `perFacilityRate` from `getRawSourceRate(itemId, item)` so pump-rate overrides are honoured.
- DO NOT pass transport capacity directly to `getPickupPointCount`. Pumps (60/min) are slower than pipes (120/min); the source-rate abstraction is the right concept.
- DO NOT re-sum pickup power at callers of `aggregateBinTotals`. It's already folded in.
